# 新能源车购车评测

> **证据驱动评价 V3.1 + 购车评测 PDF 生成 V1.0（融合版）**
> 适用于：**中国市场新能源纯电乘用车**（纯电轿车 / SUV / MPV / 跨界车型）的购车评测、车型对比、购买建议。
> 不适用于：燃油车 / 插混 / 增程 / 摩托车 / 二手车 / 泛汽车行业研究 / 汽车新闻 / 单纯参数查询。

## 这是什么？

一套面向 **新能源纯电汽车** 的**评价方法 + 自动购车评测 PDF 生成**：

1. **评价体系**：不接受"参数搬运工"式评价，把一辆车拆成 **底层技术 → 硬件能力 → 工程实现 → 实际表现 → 市场验证 → 长期可靠性 → 当前价格** 的完整证据链，最终回答三个完全不同的问题：

   > **车好不好？ ≠ 现在值不值得买？ ≠ 适不适合这个用户？**

2. **PDF 生成**：将评价结果自动渲染为一份**统一、专业、可阅读的购车评测报告**，第一页固定为评价体系介绍（方法论品牌页），严格按照「评价体系 → 产品力 → 购买价值 → 场景 → 决策 → 证据」的结构输出。

## 核心特性

### 评价体系（V3.1）

| 特性 | 说明 |
|---|---|
| **9 维产品力体系** | 能源效率 15% / 三电与补能 20% / 底盘与驾驶 15% / 安全与车身 15% / 智能驾驶 10% / 智能座舱 7.5% / 设计与体验 7.5% / 整车工程 5% / 长期可靠性 5%（固定顺序，禁止机械平均） |
| **证据双标法** | 每个数据标注 `[来源可信度][车型匹配度]`，如 C-NCAP 官方：[S][A1] |
| **来源可信度** | S 官方/C-NCAP/工信部 ｜ A 权威媒体实测 ｜ B 汽车之家/论坛 ｜ C 单博主 ｜ D 传闻（禁作关键结论） |
| **车型匹配度** | A1 同车型同版本 ｜ A2 同车型不同版 ｜ B 同平台 ｜ C 旧年款 ｜ D 间接推测 |
| **F/I/J 三级标记** | 事实 Fact / 推论 Inference / 判断 Judgment，严禁混用 |
| **评分置信度** | 分数必带置信度（高/中/低）+ 合理区间；反精度原则：宁可"7~8 分"不假装"7.4 分" |
| **反证机制** | 每个关键结论后必须自我质疑："结论可能错在哪里？" |
| **底线机制** | 安全 / 严重可靠性 / 重大质量缺陷 = 一票否决或硬性警告；重大安全证据缺口必须触发风险提示 |
| **配置四级验证** | 硬件 → 能力 → 实际表现 → 用户价值（800V≠补能优秀，激光雷达≠智驾优秀） |
| **三重独立指标** | 产品力 / 当前价格竞争力 / 场景匹配度，三个分数不合并；价格不能反向修改产品力评分 |
| **五重绑定** | 车型 → 年款/生产时间 → 版本 → 动力/电池 → 中国市场；跨版本/同平台数据必须标"参考数据" |
| **TCO 总拥有成本** | 3/5 年：购车+保险+电费+保养+维修-残值；数据不足给估算区间+假设；±5% 残值敏感度 |
| **横向对比模式** | 支持两车/多车型对比（可比性声明、9 维平行比较、购买价值对决、禁止"总分高=胜"） |
| **单车型模式** | 支持单车评测（场景矩阵"适合/注意"两列、竞品锚点参照） |
| **分析原则** | 参数不是能力；硬件不是体验；降价提升购买价值而非技术水平；禁止无证据绝对排名…… |

### PDF 生成（V1.0）

| 特性 | 说明 |
|---|---|
| **P1 = 评价体系页面（硬性）** | 无论评测什么车型，第一页固定为「我们如何评价一辆新能源纯电车？」——3×3 九宫格（图标+编号+名称+关键词）+ 四层决策横条 + FINAL DECISION；不出现任何车型名/参数/结论 |
| **固定报告结构** | P1 评价体系 → P2 车型概览 → P3+ 9 维产品力 → 当前购买价值 → TCO → 溢价分析 → 场景适配 → 最终决策 → 证据与数据质量 |
| **四层决策逻辑** | 产品力（9 维）→ 当前购买价值（价格·权益·TCO）→ 场景适配（城市·冰雪·家庭…）→ 最终决策（买/等/不买） |
| **11 种 Layout 库** | Evaluation Framework / Vehicle Hero / 9-Dimension / Score Comparison / Price / TCO / Premium / Scenario / Final Verdict / Evidence / Appendix（按内容自动选择，不套同一模板） |
| **证据呈现** | 正文只用 [S]/[A]/[B]/[C] 简码；三状态标记：已确认 / 模型估算 / 证据不足；置信度+区间+最大不确定性 |
| **设计系统** | 深蓝(理性/专业)+橙(决策/强调)双品牌色；A4 竖版；现代汽车研究机构 + 科技产品报告 + 高端编辑设计；避免 AI 模板感/emoji 滥用/彩虹色 |
| **QA 管线（16 步）** | 生成 → pymupdf 全页渲染 → contact sheet → vision 逐页检查 → 视觉/数据/分页/绑定/估算标记/证据等级检查 → 修正 → 再生成 |
| **回归测试** | 固定用例：方程豹钛7 EV 675KM 四驱闪充版 vs 小鹏G7 2026款 702 Max（基线数据入库） |

## 快速使用

### 作为 Hermes Agent Skill 安装

```bash
mkdir -p ~/.hermes/skills/automotive/ev-comprehensive-review
cp -r SKILL.md templates scripts references ~/.hermes/skills/automotive/ev-comprehensive-review/
```

之后对 Agent 说：

- "测评钛7 EV 675KM 后驱闪充版"（单车型模式）
- "钛7 和 G7 怎么选"（横向对比模式）
- "20 万纯电 SUV 推荐"（自动寻找可比竞品）

将按统一规范生成购车评测 PDF：**P1 评价体系 → 车型概览 → 9 维产品力 → 价格 → TCO → 场景 → 最终决策 → 证据**。

### 手动按体系分析

按 SKILL.md 中的流程执行：确认车型（五重绑定）→ 参数表 → 9 维评分（每维：分数+区间+置信度+最大不确定性）→ 短板/隐藏优势 → 反证 → 价格/优惠/售后 → TCO → 竞品锚点 → 最终结论（五档：推荐购买/有条件推荐/不推荐/建议等待/暂不建议）。

## 报告结构（PDF 生成规范）

```text
P1  · 评价体系（我们如何评价一辆新能源纯电车？）
P2  · 车型概览（车型/年款/版本/价格/定位/核心参数）
P3+ · 9 维产品力（每维：分数+区间+置信度+证据码+一句话依据）
    · 当前购买价值（指导价→优惠→权益→保险→实际落地，突出"实际价格差"）
    · TCO（3 年图表化，残值不足标"模型估算"）
    · 溢价分析（多花的钱买到了什么：真价值/价值有限/反向下）
    · 场景适配（场景矩阵 → "我属于哪种人"）
    · 最终决策（默认推荐 + 反选条件 + 等待情形 + 为什么）
最后 · 证据与数据质量（证据等级 + Data Quality Audit + 缺口）
```
