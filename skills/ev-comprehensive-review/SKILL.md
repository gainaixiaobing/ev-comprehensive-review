# 新能源汽车购车研究

> 轻量、证据驱动、以购买决策为导向的 Agent Skill。

## 任务定位

回答三个问题：

1. **这辆车本身怎么样？**（产品力）
2. **当前价格值不值得买？**（购买价值）
3. **适不适合这个用户？**（场景适配）

三者必须分开判断。产品力强 ≠ 值得当前价格购买 ≠ 适合所有用户。

---

## 五重绑定

研究开始前必须锁定：

> **车型 → 年款 → 具体版本 → 动力形式 → 中国市场**

跨版本/动力/年款/市场的数据必须明确标记为「参考数据」，不得伪装成目标车型实测。

---

## 研究流程

```
① 锁定车型（五重绑定）
↓ ② 明确用户需求（预算/场景/硬约束）
↓ ③ 搜集关键证据
↓ ④ 检查车型/版本匹配
↓ ⑤ 判断证据质量
↓ ⑥ 九维评价
↓ ⑦ 主动寻找反证
↓ ⑧ 数据质量审计
↓ ⑨ 产品力结论
↓ ⑩ 价格/TCO
↓ ⑪ 场景适配
↓ ⑫ 生命周期/等待价值
↓ ⑬ 最终购买建议
```

---

## 九大评价维度

固定九维，不新增：

| 维度 | 核心关注 |
|---|---|
| ① 能源效率 | 实际能耗、实际续航、高速/低温表现、补能效率 |
| ② 三电&充电 | 电池、电机、电控、电压平台、快充、电池安全 |
| ③ 底盘&驾驶 | 悬架、调校、舒适性、操控、制动、高速稳定性 |
| ④ 安全&车身 | 主被动安全、碰撞测试、车身结构、电池/高压安全 |
| ⑤ 智能驾驶 | 硬件、感知、功能覆盖、实际表现、稳定性 |
| ⑥ 智能座舱 | 芯片、车机、流畅度、语音、生态、交互 |
| ⑦ 设计&体验 | 外观、内饰、空间、座椅、人机工程、细节 |
| ⑧ 整车工程 | NVH、做工、装配、完成度 |
| ⑨ 长期可靠性 | 故障、衰减、耐久、售后、长期质量 |

每维只选**决策相关指标**，不堆参数。详见 `references/evaluation-rules.md`。

---

## 证据体系

核心判断：**这个来源可靠吗？这个数据真的属于我们正在研究的这个版本吗？**

两条规则：

1. **来源可靠性**：官方/权威测试 > 专业媒体实测 > 大规模用户数据 > 单用户/社交
2. **车型匹配度**：完全对应 > 同平台参考 > 跨市场 > 仅技术路线相似

两个条件不能同时满足 → 降低置信度。

关键区分：

- **Fact**：官方参数、权威测试、独立实测、调查数据
- **Inference**：基于多个事实的合理推断
- **Judgment**：最终评价

禁止：把厂商宣传写成独立测试结论，把推断伪装成事实。

消费者调查正式纳入证据体系，详见 `references/evidence-rules.md`。

---

## 评分

每维输出：

```
分数/10 + 置信度（高/中/低）+ 主要依据（1-2句）
```

规则：

- 证据越充分 → 评分越稳定
- 证据越不足 → 扩大不确定范围
- **没有数据 ≠ 表现差**——明确写「证据不足」
- 安全是底线指标，不被其他维度平均分覆盖

分数语义：9-10 同级标杆 ｜ 7-8.9 主流优秀 ｜ 5-6.9 及格有短板 ｜ <5 明显缺陷

## 购买决策

### 产品力

九维综合。暂不考虑价格。

### 购买价值

- 指导价
- 实际成交价（现金优惠、经销商优惠、置换补贴）
- 官方权益/限时优惠（注明有效期）
- 保险、保养、能耗 → TCO
- 保值率（数据不足时写明）

### 场景适配

结合用户实际情况：

- 预算上限
- 城市通勤 vs 高速/长途
- 年行驶里程
- 充电条件（家充/公共桩）
- 家庭成员/空间需求
- 冬季/冰雪环境
- 智驾依赖程度
- 计划持有年限

### 等待价值

必须回答 4 个问题：

1. **为什么值得等？** 新款/改款/价格变化/OTA/产能爬坡/质量问题暴露/竞品变化
2. **等什么证据？** 列出具体可观察的指标（如投诉趋势、终端价格、独立测试、大样本数据）
3. **观察多久？** 给出参考时间，但不得机械固定
4. **什么情况会改变购买结论？** 必须形成条件句：
   - 如果 X → 更倾向购买
   - 如果 Y → 继续等待
   - 如果 Z → 降低推荐/不推荐

**事件分类（必须标注）：**

| 类型 | 含义 | 示例 |
|---|---|---|
| 已知事件 | 有明确官方信息或可靠时间表 | 官方宣布 Q4 改款 |
| 高概率变化 | 有明显市场信号，但无确定时间 | 竞品密集上市，终端价格承压 |
| 不确定猜测 | 仅是一般性推测 | "价格战可能继续" |

禁止把「未来可能降价」自动写成等待理由，必须区分事件类型。

最终输出：**立即购买 / 可以购买 / 建议观察 / 建议等待 / 不推荐**

### 用户红线

硬约束拥有最高优先级。即使总分很高，违反硬约束 → 不推荐。

决策链：用户硬约束 → 产品力 → 购买价值 → 场景适配 → 最终建议

## 最终输出格式

```
# 一句话结论

## 核心优势（3-5条）
## 最大短板（3-5条）
## 九维产品力（分数+置信度+依据）
## 证据与置信度
## 当前价格值不值得
## 场景适配
## 长期风险
## 等待价值
## 最适合谁
## 不适合谁

# 最终建议
购买 / 观望 / 等待 / 不推荐
+ 核心原因（3条以内）
```

默认不展示所有参数，结论先行。用户要求深度时再展开证据。

## 横向比较

触发条件：用户提出「A 和 B 怎么选」「对比」「同价位推荐」等。

比较基础：同价位 + 同场景 + 同级别需求。

使用九维并行比较，每维说明「谁更强/为什么/是否接近」。

最终必须分别回答：产品力胜者、性价比胜者、不同场景胜者，再给最终建议。

禁止：拿明显不同级别/价格的车型直接比总分。

## Data Quality Audit

每次研究完成后检查：

- 车型/年款/版本/动力是否正确
- 数据时间是否有效
- 官方数据与实测是否混淆
- 参考数据是否被误当目标车型数据
- 是否存在明显冲突
- 是否存在关键数据缺失
- 是否存在无来源数字
- **结论强度与证据强度是否匹配**：无系统比较是否使用绝对排名；投诉占比是否被写成故障率；单一案例是否被泛化；跨车型证据是否被直接归因；不确定事件是否被写成确定事件

输出：数据质量（高/中/低）+ 主要缺口

---

## 研究原则

1. **先锁车型，再找数据**
2. **先证据，再结论**
3. **事实、推断、判断必须分开**
4. **不确定就是不确定，不编造**
5. **没有数据 ≠ 表现差**
6. **主动寻找反证，而不是寻找支持**
7. **参数数量 ≠ 研究质量**
8. **产品力、购买价值、场景适配必须分开**
9. **用户硬约束优先于总分**
10. **研究最终回答「买不买」，而不是「这辆车有什么参数」**
